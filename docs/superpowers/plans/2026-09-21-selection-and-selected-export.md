# Selection UX and selected-page export

**Goal:** Let users choose pages efficiently on desktop or touch devices and download exactly those pages without changing the workspace.

**Basis:** The approved product design and P1 Selection UX / Save selected pages milestones in `plan/2026-09-19-product-roadmap-checklist.md`. The user explicitly authorized both features after full-page preview, retaining `gpt-5.6-sol` high for code and tests. Root owns requirements, integration and acceptance; one Sol implementer owns the coupled code and tests.

## Current design and constraints

- Keep the existing thumbnail single-selection and Ctrl/Cmd additive toggle. Shift-click selects the inclusive range in current workspace order from the last intentional page-selection target; Ctrl/Cmd+Shift adds that range to the existing set. Repeated Shift operations keep the anchor. Without a valid anchor, select the clicked page and establish it as anchor.
- Add visible, labeled page checkboxes for additive selection without modifiers on desktop, keyboard and touch. Checkbox changes also establish the anchor. Place them beside the existing drag handle, outside the document image; never nest interactive controls or cover Preview/reorder controls. Thumbnail single-selection and checkbox additive-selection remain distinguishable in help copy.
- Add Select all and Deselect all controls and one prominent selected-count status in the editing toolbar. Keep the document header's total page count without duplicating the live selection announcement. Preserve explicit non-drag movement and the preview entry.
- Selection changes do not create undo steps. Track the range anchor by page ID outside persisted/history workspace data: reordering keeps the anchor identity; duplication does not retarget it; deletion of the anchor clears it; restore, Select all and Deselect all clear it. Undo/redo must never leave an invalid anchor. Do not migrate recovery records.
- Delete, Duplicate and Rotate continue to operate on the complete selected set. Preview rotation still affects only its displayed page without changing selection. Disable new controls under the same busy/export/recovery/drag conditions as other edits.
- Keep Save PDF as the primary all-pages action, with explicit all-pages copy. Show a secondary Save selected pages action only when selection is non-empty; display its count and reuse the same password validation/confirmation settings.
- Build a fresh selected export snapshot from workspace order, not selection-click order, without mutating page order, selection, history, documents or source bytes. Reject empty or invalid/stale requested selection visibly rather than silently dropping requested pages. Existing engine validation remains authoritative for missing source and invalid source-page references.
- Reuse the existing export worker, additive rotations, duplicates, mixed sources, password flow, progress and cancellation. Progress totals must refer to the submitted snapshot, including the initial progress state. Cancelling or failing creates no download, preserves workspace/selection and allows retry. Use `quack-honk-selected-pages.pdf` for a selected export and retain the existing all-pages filename.
- Keep every document operation browser-local. Add no dependencies, upload endpoint, analytics or remote storage. Keep original bytes and existing source-password/recovery behavior. Preserve the existing chunk-warning threshold and privacy assertions.
- Preserve desktop and 390px usability, keyboard labels/focus and reduced motion. New selection controls should remain usable alongside the existing page-editing toolbar without excessive mobile height.

## Review focus

- Range anchor identity after reorder, duplicate, deletion, undo/redo and restore; selections contain only valid unique IDs.
- Explicit mobile multi-selection without accidentally opening preview or starting drag; keyboard-only completion and toolbar density at 390px.
- Multi-page deletion/rotation/duplication targets exactly the intended selected set and remains undoable.
- Selected output follows workspace order and fails visibly for any invalid requested page; all-pages export stays all-pages.
- Cancellation/failure/password retry preserves original bytes and the entire workspace/selection; progress never counts unrequested pages.
